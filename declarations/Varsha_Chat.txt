6 Reflections

Kamalanathan Varsha

What did you learn?
I learned that polymorphism is more than a textbook idea. It is what let us add new customer kinds without touching the game flow. I wrote VIPCustomer and CriticCustomer.

How did you apply it?
In Stage 2 we made the points where customers differ (getWaitLoss, discountedPrice, chooseItem, reviewedSatisfaction) overridable hooks. This is the Open/Closed Principle in practice. Stage 2 added three classes and changed only three small files, and GameController and Restaurant were untouched.

What challenged you?
The hardest part was deciding what belonged in the base Customer class and what belonged in a subclass. If the base contract was too narrow, the Critic's review rule had nowhere to fit.

How did you solve it?
We settled on a reviewedSatisfaction() hook with a guarantee that results stay within 0..100, so every subclass can still be used wherever a Customer is expected (Liskov). I learned to design the contract before writing the subclasses.


Pachipala Aishwarya

What did you learn?
I learned how much correctness depends on the order in which things happen in a turn-based system. I implemented the turn loop in GameController.

How did you apply it?
GameController follows the six required steps. Because choices are applied immediately in the fixed order Host -> Waiter -> Chef, a dish that becomes READY this turn can never be served this turn. Order.markServed also checks readyTurn < turn as a second guard.

What challenged you?
Happy Hour timing was the trickiest part. It had to be accepted only before any staff member had acted, last for two turns, and still leave earlier prices unchanged.

How did you solve it?
We added anyStaffHasActed() and locked each bill at order time. I also learned the value of validating before consuming a task. InvalidActionException is thrown before markActed(), so an invalid choice never costs the player a turn.


Shah Anand Aashka

What did you learn?
I learned that small data-representation choices can prevent whole classes of bugs. I implemented Money and Scoreboard.

How did you apply it?
We stored all money as integer cents, with half-up rounding only in Money.percentOf. This made the stacked VIP and Happy Hour price exact: 1800 x 0.9 x 0.8 = 1296 cents. The win rule compares total >= 60 x paid in integers, so no rounding can flip the result.

What challenged you?
Testing without a framework was difficult. We needed to know that Stage 1 behaviour still worked after Stages 2 and 3.

How did you solve it?
We saved deterministic input scripts (e.g. stage3_victory, stage3_no_happyhour) and compared each replay against hand-calculated numbers. This gave us evidence that earlier behaviour was preserved and that each manager choice changed the result as expected.
